# 활동지 만들기

Claude, Claude Code, Codex에서 공통으로 사용하는 스킬이다. 파일 작성과 Python 실행이 가능한 환경에서 동봉된 편집기를 연결한다. 브라우저가 없는 환경에서는 가능한 정적 검증을 하고 화면·인쇄·조작 중 확인하지 못한 항목을 밝힌다. 특정 제품 전용 도구 이름을 가정하지 않는다.

교사의 의도를 학생이나 연수 참여자의 **구체적인 행동과 결과물**로 옮긴다. 보기 좋은 지면과 실제로 쓸 수 있는 답란을 함께 설계한다. 결과는 브라우저에서 바로 수정하고 다시 저장할 수 있는 독립 HTML이다.

## 요청에서 설계로

- 이미 주어진 대상·주제·자료·목적·사용 방식을 먼저 정리한다. 수업 대상이 학생인지 연수 참여 교사인지 구분한다.
- 결과를 크게 바꾸는 정보만 짧게 묻는다. 사용자가 주제나 디자인을 맡겼으면 적절하게 선택해 진행한다. 질문지나 승인 절차를 일괄 강제하지 않는다.
- 작업 전에 `대상 / 활동의 목적 / 참여자가 할 일 / 남길 결과 / 화면·인쇄 용도 / 시각 방향`을 짧게 정한다. 불확실한 가정만 사용자에게 알린다.
- 자료가 필요한 활동은 먼저 자료를 준비한다. 제공한 원문과 출처를 유지하고, 수치·인용은 확인한다. 작품명만 보고 원문을 재현하지 않는다. 실제 조사처럼 보이는 가상 자료에는 ‘수업용 가상 사례’처럼 맥락을 밝혀 혼동을 막는다. 별도 AI 생성 배지는 강제하지 않는다.

## 내용에 맞는 지면

인쇄용 활동지는 종이·자료 상자·답란을 흰색으로 두고, 본문 표의 머리글 행에는 옅은 음영을 사용해 항목을 구분한다. 글자·선·의미 있는 그림의 포인트 색도 사용할 수 있다. 스타일 이름이나 색상 변경보다 실제 배치의 차이를 먼저 설계한다. 같은 주제라도 자료와 응답을 나란히 놓는 지면, 중심 질문에 생각을 연결하는 지면, 큰 작업 공간과 여백 메모를 조합하는 지면 중 활동에 맞는 구성을 고른다. 활동 세 개를 위에서 아래로 반복하는 양식을 기본으로 강제하지 않는다.

자료 뒤에 번호가 있는 질문과 답란을 순서대로 두는 기본형, 질문과 응답을 한 표에 놓는 기본형도 동등하게 고려한다. 다양성을 위해 익숙한 기본형을 배제하거나 불필요하게 복잡한 배치를 만들지 않는다. 제목부는 수업 주제와 인적 사항을 짧게 제시한다. A4는 제목 16~20pt 정도에서 검토하고, 불필요한 수동 줄바꿈·큰 상하 여백·홍보성 부제는 줄인다. 제목 길이에 따라 자연스럽게 늘어나게 하되 본문과 쓰기 공간을 먼저 확보한다.

기본 머리글은 과목·차시를 **표 밖 윗줄**에 두고, 아래 표의 첫 행을 합쳐 제목을 가운데 정렬한다. 다음 행에는 학급·번호·이름을 둔다. 교사 연수는 과목 대신 연수 주제, 학급 대신 소속·모둠 등 대상에 맞게 바꾼다. 짧은 활동 안내는 표 아래에 둔다. 과목·차시와 제목·인적 사항을 모두 편집 가능하게 한다. 사용자가 다른 머리글을 지정하면 그 요구를 우선한다.

1. 활동을 수행하는 순서에 맞춰 발문과 자료를 배치한다. 학습 결과를 남기는 칸을 먼저 확보하고 나머지를 조정한다.
2. 활동 번호와 필요한 하위 문항 번호를 눈에 띄게 구분한다. 자료에 이름을 붙여 발문에서 정확히 가리킨다.
3. 선택·단답·비교·긴 서술·그림·관찰 기록에 맞게 답란의 모양과 크기를 달리한다. 모든 활동에 같은 표나 큰 빈 상자를 반복하지 않는다.
4. 도움 질문은 필요할 때 답란 근처에 짧게 둔다. 정답을 대신 채우지 않는다. 짝의 피드백이 수정으로 이어지는 활동이라면 둘 다 기록할 공간을 마련한다.
5. 인쇄용은 특별한 요구가 없으면 A4로 시작하되, 분량을 무조건 1~2쪽에 맞추지 않는다. 글씨나 쓰는 공간을 줄여 억지로 압축하지 않는다. 화면 전용이라면 종이 쪽 모델을 강제하지 않는다.

인쇄 미리보기에서 하단이 크게 비어 있으면 긴 서술 답란, 스케치·계산 영역에 그 공간을 재배분한다. 제목이나 본문 글씨를 키우거나 꼬리말만 아래로 밀어 빈 공간을 가리지 않는다. 병렬 배치에서는 나란한 작업 영역의 실제 높이를 함께 확인한다. 답란의 높이는 편집 모드·미리보기·PDF에서 유지되어야 하며, 이후 내용이 늘면 잘리지 않고 흐르게 한다.

디자인을 정할 때만 [시각 방향과 지면 판단](references/design-directions.md)을 읽는다. 필요한 구성 요소가 있을 때 [컴포넌트 재료](references/material-patterns.md)에서 해당 부분만 참고한다. 예시는 고정 양식이나 허용 목록이 아니다. 다른 배치와 새로운 컴포넌트를 직접 만들어도 된다.

## HTML 작성과 편집

수식·좌표평면·함수 그래프·통계 그래프·과학 도식이 필요한 요청에는 [수식과 그래프](references/math-and-graphs.md)를 읽는다. 원식·수치에서 정확하게 렌더하고 원자료를 HTML에 남긴다. 수식이나 그래프를 생성할 수 있다는 것과 공통 편집기로 내부까지 직접 편집할 수 있다는 것은 구분해 안내한다.

수식에는 `data-math`, LaTeX 원문인 `data-latex`, 문장 안/별도 줄을 정하는 `data-display`를 사용한다. 동봉된 KaTeX 편집창으로 원문·미리보기·적용·취소, 자주 쓰는 수식 입력, 되돌리기와 오프라인 저장을 지원한다. 그래프·도형은 별도로 작성하고 확인한다.

수학 예시는 학년·단원·한 차시의 목표를 먼저 정한다. 구성 요소를 많이 보여 주려고 분수·방정식·함수 등 다른 단원을 임의로 섞지 않는다. 기초 확인, 핵심 유형의 안내, 독립적인 적용, 검산처럼 실제 수업의 흐름과 난도에 맞춰 문제를 고른다. 단순 계산에는 짧은 공간을, 식 세우기와 논증에는 충분한 풀이 공간을 둔다. 혼합 복습은 사용자가 그 목적을 요청한 경우에 구성한다.

- 요청에 맞는 HTML/CSS를 **직접 작성**한다. 이전 결과물의 색만 바꾸는 방식으로 새 디자인을 대신하지 않는다.
- 활동지와 해설·진행자 자료가 각각 필요하면 독립 파일로 만든다. 교사본을 원본으로 두고 학생본을 추출하는 흐름은 기본 기능이 아니다. 배포할 HTML에도 편집 기능을 유지한다.
- [편집 연결 방법](references/editing.md)에 따라 본문 컨테이너, 수정할 글·셀, 이동할 영역을 표시한다. 표시 속성은 편집 연결용이며 컴포넌트 종류나 디자인을 제한하지 않는다.
- 그림은 문서 안에 포함한다. 외부 폰트·CDN·이미지 주소를 필수 의존으로 두지 않는다. 수식·복잡한 도표가 필요할 때만 그에 맞는 렌더링 도구를 사용하고 결과 자원을 HTML에 포함한다.
- 공통 편집기는 선택한 대상에 맞춰 글꼴·서식·정렬·줄 간격, 답란 높이·괘선, 표 행·열 추가/삭제·너비/높이, 이미지 교체·크기, 영역 복제·이동·삭제 도구를 보여 준다. 답란에는 `data-answer-space` 표시를 붙인다. 되돌리기, HTML 다운로드 저장, 인쇄와 KaTeX 수식 편집도 지원한다. 특수 도형의 내부 조작이 필요하면 해당 요소에 별도로 연결한다.

```text
python <이 스킬 경로>/scripts/attach_editor.py 초안.html --output 활동지.html --kind worksheet
```

이 명령은 편집 기능만 붙인다. 지면이나 색상, 페이지 수를 만들지 않는다. 기존 파일을 수정할 때는 내용을 먼저 읽고 보존한다. 새 파일로 저장하거나, 명시적으로 필요한 경우에만 `--overwrite`를 사용한다.

## 결과 확인과 전달

- 실제 브라우저에서 글·표를 고치고 HTML을 저장한 뒤 다시 열어 수정 내용이 남는지 확인한다. 사용한 주요 컴포넌트의 편집도 확인한다.
- 화면의 잘림·겹침·지나치게 작은 글씨를 본다. 인쇄용이면 PDF를 뽑아 문항과 답란의 연결, 쓰는 공간, 쪽 넘김을 확인한다. 로컬 HTML의 브라우저 검증은 HTTP로 연다.
- 바뀐 부분과 대표 지면에 맞춰 검증한다. 단순 자료 수정에 전체 엔진 회귀 검사나 모든 스타일의 재검증을 붙이지 않는다.
- HTML 링크와 꼭 필요한 사용법을 전달한다. 검증하지 못한 항목은 구분해 알린다. 전체 생성 과정이나 내부 설계 용어를 결과물에 넣지 않는다.
